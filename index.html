Memory Architecture

Understanding how embedded systems organize memory

🗺️

Memory Map

Beginner
Stack ↓0x20020000
↕ Free Memory
Heap ↑0x20000400
BSS (Uninitialized)0x20000200
Data (Initialized)0x20000100
Text (Code)0x08000000

Stack grows downward from the top of SRAM (0x20020000 on a 128 KB STM32F407 — the initial SP is the first word of the vector table) and stores local variables and function call frames. Heap grows upward and is used for dynamic allocation. BSS holds zero-initialized global variables, while Data stores initialized globals. Text is your compiled code stored in Flash.

📚

Stack

Beginner

The stack is a LIFO (Last-In, First-Out) data structure used for local variables, function call frames, and return addresses. It grows downward from the top of RAM. Stack memory is automatically allocated on function entry and freed on return.

stack_example.c 
void process_data(void) {
    uint8_t buffer[64];    // Stack
    uint32_t counter = 0;  // Stack
    // Auto-freed on return
}
🏔️

Heap

Beginner

The heap is used for dynamic memory allocation at runtime. In embedded systems, heap usage is discouraged because it introduces fragmentation risks, non-deterministic timing, and potential memory leaks — all dangerous in safety-critical systems.

heap_example.c 
// ⚠️ Use carefully in embedded!
uint8_t *buf = (uint8_t*)malloc(256);
if (buf != NULL) {
    memset(buf, 0, 256);
    // ... use buffer ...
    free(buf);
}
🧪

Interactive Memory Visualizer

Interactive

Experiment with stack and heap allocation. Stack variables appear when a function runs and disappear when it returns; heap blocks stay until you call free(). If the two regions meet, you have a stack overflow — one of the most common embedded crashes.

🔥

Volatile

Intermediate

The volatile keyword tells the compiler that a variable's value can change at any time — by hardware, an interrupt, or another thread. Without it, the compiler may optimize away reads, causing your code to miss hardware changes.

volatile_example.c 
// Without volatile: compiler may read once
// and spin forever on a cached value.
// With volatile: re-read on every access.
#define USART1_SR (*(volatile uint32_t *)0x40011000)
#define SR_TXE    (1U << 7)   // TX data register empty

while (!(USART1_SR & SR_TXE)) {
    // Wait until hardware sets the ready bit
}
📌

Static & Const

Beginner

static variables inside functions persist across calls — they live in the .data or .bss segment, not on the stack. const data is typically stored in Flash (.rodata), saving precious RAM on memory-constrained MCUs.

static_const.c 
void count_calls(void) {
    static uint32_t count = 0;  // .bss (zero-init)
    static uint32_t boots = 1;  // .data (non-zero init)
    count++;
}

const uint8_t lookup[] = {0,1,1,2,3,5,8};
// Stored in Flash (.rodata)

Type Casting

Intermediate

Casting between types is essential in embedded C, but conversions that don't fit the target type silently change the value. Always be explicit about casts and understand the data ranges.

casting.c 
uint8_t sensor_val = 200;
int8_t signed_val = (int8_t)sensor_val;
// signed_val = -56 on GCC/ARM: 200 doesn't fit
// in int8_t (max 127), result is impl.-defined

uint16_t adc_raw = 3000;
float voltage = (float)adc_raw / 4095.0f * 3.3f;
🔄

Endianness

Intermediate

Endianness determines the byte order when storing multi-byte values. ARM Cortex-M is little-endian by default, but network protocols use big-endian. You must handle conversion when communicating between systems.

Big-Endian (Network Order)

0xDE 0xAD 0xBE 0xEF
addr → addr+3

Little-Endian (ARM, x86)

0xEF 0xBE 0xAD 0xDE
addr → addr+3
endian.c 
uint32_t value = 0xDEADBEEF;
uint8_t *bytes = (uint8_t*)&value;
// On little-endian ARM:
// bytes[0] = 0xEF, bytes[1] = 0xBE
// bytes[2] = 0xAD, bytes[3] = 0xDE
📦

Struct Packing

Intermediate

Compilers add padding bytes for alignment, wasting precious memory. Use __attribute__((packed)) to eliminate padding — but beware of alignment faults on some architectures.

struct_packing.c 
// With padding: 12 bytes!
struct sensor_data {
    uint8_t  id;       // 1 + 3 padding
    uint32_t timestamp; // 4
    uint16_t value;     // 2 + 2 padding
};

// Packed: 7 bytes
struct __attribute__((packed)) sensor_packed {
    uint8_t  id;        // 1
    uint32_t timestamp; // 4
    uint16_t value;     // 2
};

Beginner

Check a Bit

Beginner

Use the AND operator to test whether a specific bit is set. The result is non-zero if the bit is 1.

check_bit.c 
// Check if bit n is set

    // Bit is set
}

// Example: Read button on pin 0

    button_pressed = 1;
}

Bit Masks

Intermediate

Bit masks let you isolate, modify, or test groups of bits simultaneously. Define them as named constants for readability. The pattern of "clear then set" is essential for multi-bit fields like GPIO mode registers.

bit_masks.c 
#define LED_MASK    0x0F    // Bits 0-3
#define STATUS_MASK 0xF0    // Bits 4-7

// Apply mask to read specific bits
uint8_t leds = PORT & LED_MASK;

// Clear then set a field in ONE write
// (two separate writes would briefly
//  output a glitch value on real pins)
uint32_t tmp = REG;
tmp &= ~LED_MASK;            // Clear field
tmp |= (value & LED_MASK);   // Insert new value
REG = tmp;

Pointers & Memory Access

The bridge between software and hardware

👆

Pointer Fundamentals

Beginner

A pointer is a variable that stores the memory address of another variable. In embedded C, pointers are your primary tool for accessing hardware registers and manipulating memory directly.

sensor_reading 42 0x20000004
←
ptr 0x20000004 0x20000008
pointers.c 
int32_t sensor_reading = 42;
int32_t *ptr = &sensor_reading;

*ptr = 100;  // sensor_reading is now 100

printf("Value: %ld\n", (long)*ptr); // 100
printf("Address: %p\n", (void*)ptr); // 0x20000004
➕

Pointer Arithmetic

Intermediate

When you increment a pointer, it advances by the size of the type it points to — not by one byte. This is crucial when traversing arrays or memory-mapped registers.

ptr_arithmetic.c 
uint8_t data[4] = {0xAA, 0xBB, 0xCC, 0xDD};
uint8_t *p = data;

p++;               // moves 1 byte (sizeof(uint8_t))
uint8_t v = *p;    // v = 0xBB

uint32_t *p32 = (uint32_t*)data;
p32++;             // moves 4 bytes (sizeof(uint32_t))
// ⚠️ Casting a byte array to uint32_t* can be
// misaligned — use memcpy() in real code.
📞

Function Pointers

Intermediate

Function pointers store the address of a function. They're used extensively in embedded systems for interrupt vector tables, callback mechanisms, and state machines.

func_pointers.c 
typedef void (*handler_t)(void);

void led_on(void)  { GPIOA->BSRR = (1U << 5); }
void led_off(void) { GPIOA->BSRR = (1U << 21); }

// Table of callbacks (same idea as the
// interrupt vector table in startup code)
handler_t actions[] = { led_off, led_on };

// Call via pointer
actions[state]();
🔌

Memory-Mapped I/O

Intermediate

This is THE most important concept in embedded C. Hardware peripherals (GPIO, UART, SPI, etc.) have control registers at fixed memory addresses. By writing to those addresses with pointers, you directly control the hardware. There's no OS, no abstraction layer — just you and the silicon.

mmio.c 
// Direct register access
#define GPIOA_BASE  0x40020000
#define GPIOA_MODER (*(volatile uint32_t*)(GPIOA_BASE + 0x00))
#define GPIOA_ODR   (*(volatile uint32_t*)(GPIOA_BASE + 0x14))

#define RCC_AHB1ENR (*(volatile uint32_t*)0x40023830)

// Now use like variables!
RCC_AHB1ENR |= (1U << 0);       // GPIOA clock on
GPIOA_MODER &= ~(3U << 10);     // clear MODER5
GPIOA_MODER |=  (1U << 10);     // PA5 output
GPIOA_ODR   |=  (1U << 5);      // PA5 high
🏗️

Struct Overlay

Advanced

The professional approach: define a struct that mirrors the register layout and cast the base address to a struct pointer. This is how STM32 HAL/CMSIS headers work!

struct_overlay.c 
typedef struct {
    volatile uint32_t MODER;   // 0x00
    volatile uint32_t OTYPER;  // 0x04
    volatile uint32_t OSPEEDR; // 0x08
    volatile uint32_t PUPDR;   // 0x0C
    volatile const uint32_t IDR; // 0x10 (read-only)
    volatile uint32_t ODR;     // 0x14
} GPIO_TypeDef;

#define GPIOA ((GPIO_TypeDef*)0x40020000)

GPIOA->ODR |= (1U << 5);

GPIO Configuration

Intermediate

Configuring a GPIO pin for output requires setting multiple registers: clock enable, pin mode, output type, speed, and pull-up/pull-down. Here's the complete 5-step process for PA5 (the user LED on Nucleo boards).

gpio_config.c 
// 1. Enable GPIO clock
RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;

// 2. Set pin mode (Output)
GPIOA->MODER &= ~(3U << 10);  // Clear
GPIOA->MODER |=  (1U << 10);  // Set output

// 3. Set output type (Push-Pull)
GPIOA->OTYPER &= ~(1U << 5);

// 4. Set speed (Fast = 0b10)
GPIOA->OSPEEDR &= ~(3U << 10);
GPIOA->OSPEEDR |=  (2U << 10);

// 5. No pull-up/pull-down
GPIOA->PUPDR &= ~(3U << 10);
✏️

Read-Modify-Write

Intermediate

Never directly assign a register value unless you want to overwrite all bits. Always use the read-modify-write pattern to change only the bits you need.

rmw.c 
// ❌ Wrong: Overwrites other bits!
GPIOA->MODER = (1U << 10);

// ✅ Correct: Read-Modify-Write
uint32_t temp = GPIOA->MODER;
temp &= ~(3U << 10);  // Clear bits 10-11
temp |=  (1U << 10);  // Set bit 10
GPIOA->MODER = temp;

Bit-Banding

Advanced

ARM Cortex-M3/M4 (e.g. STM32F4) provide a "bit-band" region that maps each bit of peripheral/SRAM memory to a unique 32-bit alias address. Writing to the alias sets or clears the bit atomically — no read-modify-write needed!

bit_banding.c 
// Bit-band alias for atomic bit access
#define BB_ADDR(reg, bit) \
  (0x42000000UL + (((reg) - 0x40000000UL) * 32UL) + ((bit) * 4UL))

// Set bit 5 of GPIOA->ODR atomically
*((volatile uint32_t*)BB_ADDR(0x40020014, 5)) = 1;
// (Not available on Cortex-M0/M7/M33 — use BSRR there)

Interrupts & ISRs

Responding to real-time events in hardware

How Interrupts Work

Intermediate

When an interrupt fires, the CPU automatically saves context (key registers), jumps to the Interrupt Service Routine (ISR), executes it, restores context, and resumes the main code. This all happens in hardware — fast and deterministic.

Main Code Running
⚡ IRQ Fires!
Context Saved (Push R0-R3, R12, LR, PC, xPSR)
→
ISR Executes
→
Context Restored (Pop registers)
→
Main Code Resumes
📋

ISR Best Practices

Intermediate
  • ✅ Keep ISRs short and fast
  • ✅ Set a flag, process in main loop
  • ✅ Use volatile for shared variables
  • ❌ No malloc/free in ISRs
  • ❌ No printf or blocking calls
  • ❌ No long loops
isr_pattern.c 
#define RX_SIZE 64
volatile uint8_t rx_buffer[RX_SIZE];
volatile uint8_t idx = 0;
volatile uint8_t data_ready = 0;

void USART1_IRQHandler(void) {
    if (USART1->SR & USART_SR_RXNE) {
        uint8_t b = (uint8_t)USART1->DR; // read clears RXNE
        if (idx < RX_SIZE) rx_buffer[idx++] = b;
        data_ready = 1;  // main loop does the work
    }
}
🎚️

NVIC Configuration

Advanced

The Nested Vectored Interrupt Controller (NVIC) manages interrupt priorities and enables/disables specific interrupt lines on ARM Cortex-M processors.

nvic_config.c 
// Configure External Interrupt on PA0

// 1. Enable GPIOA + SYSCFG clocks
//    (PA0 is an input after reset)
RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
RCC->APB2ENR |= RCC_APB2ENR_SYSCFGEN;

// 2. Select PA0 for EXTI0
SYSCFG->EXTICR[0] &= ~0xFU;

// 3. Enable rising edge trigger
EXTI->RTSR |= (1U << 0);

// 4. Unmask EXTI0
EXTI->IMR |= (1U << 0);

// 5. Enable in NVIC
NVIC_SetPriority(EXTI0_IRQn, 2);
NVIC_EnableIRQ(EXTI0_IRQn);

// 6. The handler MUST clear the pending bit,
//    or it re-enters forever
void EXTI0_IRQHandler(void) {
    if (EXTI->PR & (1U << 0)) {
        EXTI->PR = (1U << 0);  // write 1 to clear
        button_flag = 1;
    }
}

Critical Sections

Advanced

When main code and ISRs share data, you must protect access to prevent race conditions. Disabling interrupts briefly creates a "critical section" where no preemption can occur.

critical_section.c 
// Method 1: Disable/Enable all interrupts
__disable_irq();
shared_counter++;  // Safe access
__enable_irq();

// Method 2: Save and restore state
uint32_t primask = __get_PRIMASK();
__disable_irq();
shared_data = new_value;
__set_PRIMASK(primask);

Volatile Deep Dive

Intermediate

Without volatile, the compiler may optimize away "redundant" writes to the same address. But for hardware registers, every write has a side effect!

volatile_deep.c 
// ❌ Compiler may optimize this:
uint32_t *reg = (uint32_t*)0x40020014;
*reg = 1;  // Compiler: "I'll keep this..."
*reg = 2;  // Compiler: "...and skip this!"

// ✅ volatile prevents optimization:
volatile uint32_t *reg = 
    (volatile uint32_t*)0x40020014;
*reg = 1;  // Write happens
*reg = 2;  // This write also happens

Universal Asynchronous Receiver-Transmitter — two devices talk over TX and RX with a shared baud rate, no shared clock. Each byte is framed as idle-high → start bit (0) → 8 data bits (LSB first) → stop bit (1). Common for debug consoles, GPS, and Bluetooth modules.

  • Wires: TX, RX, GND (sometimes RTS/CTS)
  • Strength: simple, full-duplex, point-to-point
  • Watch for: baud mismatch and crossed TX/RX

SPI in brief

Serial Peripheral Interface — a master clocks data to/from slaves with a shared clock. Full-duplex: MOSI and MISO shift at the same time. Chip Select (CS) picks which slave is active. Fast and common for displays, flash, and ADCs.

I2C in brief

Inter-Integrated Circuit — a shared two-wire bus (SDA + SCL) with pull-ups. Devices have 7-bit addresses. A write often looks like START → address+W → ACK → register → ACK → data → ACK → STOP. Great for sensors and EEPROMs on few pins.

UART Setup

Intermediate

UART (Universal Asynchronous Receiver-Transmitter) is the most common debugging and communication interface. Here's a complete setup for USART1 on STM32F4 using PA9 (TX) and PA10 (RX).

uart_init.c 
void uart_init(uint32_t baud) {
    // Enable clocks
    RCC->APB2ENR |= RCC_APB2ENR_USART1EN;
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
    
    // PA9=TX, PA10=RX: alternate function mode
    GPIOA->MODER &= ~((3U << 18) | (3U << 20));
    GPIOA->MODER |=   (2U << 18) | (2U << 20);
    // AF7 = USART1 (AFRH: PA9 bits 7:4, PA10 bits 11:8)
    GPIOA->AFR[1] &= ~((0xFU << 4) | (0xFU << 8));
    GPIOA->AFR[1] |=   (7U << 4) | (7U << 8);

    // Baud: USART1 is on APB2 (PCLK2 = 84 MHz
    // on a 168 MHz F407), OVER8 = 0, rounded
    uint32_t pclk2 = 84000000UL;
    USART1->BRR = (pclk2 + baud / 2) / baud;
    USART1->CR1 = USART_CR1_TE | USART_CR1_RE
                | USART_CR1_UE;          // 8N1 default
}

void uart_send(uint8_t ch) {
    while (!(USART1->SR & USART_SR_TXE));
    USART1->DR = ch;
}

DMA Transfers

Advanced

Direct Memory Access (DMA) transfers data between memory and peripherals without CPU involvement. Set it up once, fire it, and the CPU is free to do other work.

dma_uart.c 
// USART1_TX = DMA2 Stream7 Channel4
RCC->AHB1ENR |= RCC_AHB1ENR_DMA2EN;

DMA2_Stream7->CR &= ~DMA_SxCR_EN;
while (DMA2_Stream7->CR & DMA_SxCR_EN);  // wait off
DMA2->HIFCR = DMA_HIFCR_CTCIF7 | DMA_HIFCR_CHTIF7
            | DMA_HIFCR_CTEIF7 | DMA_HIFCR_CDMEIF7
            | DMA_HIFCR_CFEIF7;              // clear flags

DMA2_Stream7->PAR  = (uint32_t)&USART1->DR;
DMA2_Stream7->M0AR = (uint32_t)tx_buffer;
DMA2_Stream7->NDTR = buffer_len;
DMA2_Stream7->CR   = DMA_SxCR_CHSEL_2      // channel 4
                   | DMA_SxCR_MINC         // mem++
                   | DMA_SxCR_DIR_0        // mem → periph
                   | DMA_SxCR_TCIE;        // IRQ when done

USART1->CR3 |= USART_CR3_DMAT;   // UART requests DMA
DMA2_Stream7->CR |= DMA_SxCR_EN; // fire and forget!

🏗️

Timer Architecture

Intermediate

A timer is a hardware counter clocked by its bus timer clock (APB1 or APB2), divided by a prescaler. When the counter reaches the Auto-Reload Register (ARR) value, it generates an update event and restarts from 0. On a 168 MHz STM32F407, APB1 runs at 42 MHz and its timers (TIM2–TIM7) are clocked at 2 × 42 = 84 MHz.

Update frequency = Clock / (PSC + 1) / (ARR + 1). For a 1 Hz blink: 84 MHz / (8399 + 1) / (9999 + 1) = 1 Hz. Both registers hold value − 1 because the hardware counts from 0.

Timer Setup

Intermediate

Configure TIM2 to generate a 1 Hz interrupt for LED blinking. The prescaler divides the 84 MHz clock, and the ARR sets the period.

timer_setup.c 
void timer_init(void) {
    RCC->APB1ENR |= RCC_APB1ENR_TIM2EN;
    
    TIM2->PSC = 8399;    // 84MHz/8400 = 10kHz
    TIM2->ARR = 9999;    // 10kHz/10000 = 1Hz
    TIM2->EGR = TIM_EGR_UG;      // load PSC now (it's buffered)
    TIM2->SR  = 0;               // drop the UG flag
    TIM2->DIER |= TIM_DIER_UIE;  // Enable interrupt
    TIM2->CR1 |= TIM_CR1_CEN;    // Start!

    NVIC_EnableIRQ(TIM2_IRQn);
}

void TIM2_IRQHandler(void) {
    if (TIM2->SR & TIM_SR_UIF) {
        TIM2->SR = ~TIM_SR_UIF;  // rc_w0: write 0 to clear
        toggle_led();
    }
}

Input Capture

Advanced

Input capture mode records the timer counter value when an external signal edge occurs. By measuring the difference between two captures, you can calculate the signal's frequency.

input_capture.c 
// Measure frequency of external signal
#define TIMER_CLK_HZ 1000000UL  // TIM3 tick after PSC
volatile uint16_t captures[2];
volatile uint8_t  capture_idx = 0;
volatile float    measured_freq = 0;

void TIM3_IRQHandler(void) {
    if (TIM3->SR & TIM_SR_CC1IF) {
        // Reading CCR1 also clears CC1IF
        captures[capture_idx] = (uint16_t)TIM3->CCR1;
        if (++capture_idx >= 2) {
            // 16-bit timer: uint16_t math handles wrap
            uint16_t period = (uint16_t)(captures[1] - captures[0]);
            if (period) measured_freq = (float)TIMER_CLK_HZ / period;
            capture_idx = 0;
        }
    }
}

Watchdog Timer

Intermediate

A watchdog timer is a safety mechanism that resets the MCU if your software hangs. You must periodically "feed" (reset) the watchdog counter. If you don't — something crashed — the MCU reboots automatically. STM32 has two: IWDG (runs from its own ~32 kHz LSI clock, so it survives a main-clock failure, and cannot be stopped once started) and WWDG (windowed: feeding too early also resets).

watchdog.c 
// Independent Watchdog (IWDG)
// Must be "fed" periodically or MCU resets

void iwdg_init(uint32_t timeout_ms) {
    // LSI ≈ 32 kHz, /64 → 0.5 kHz → 2 ms per count
    uint32_t rlr = timeout_ms / 2;
    if (rlr > 4095) rlr = 4095;   // max ≈ 8.19 s

    IWDG->KR  = 0xCCCC;  // Start watchdog
    IWDG->KR  = 0x5555;  // Unlock PR/RLR
    IWDG->PR  = 4;       // Prescaler /64
    IWDG->RLR = rlr;
    while (IWDG->SR);    // wait for PVU/RVU to clear
    IWDG->KR  = 0xAAAA;  // Reload with new value
}

// Call periodically in main loop:
void iwdg_feed(void) {
    IWDG->KR = 0xAAAA;  // Reset counter
}

SysTick

Beginner

SysTick is a 24-bit countdown timer built into every ARM Cortex-M core. It's perfect for creating a millisecond tick — the foundation of delay_ms() and RTOS tick sources.

systick.c 
volatile uint32_t systick_ms = 0;

void SysTick_Handler(void) {
    systick_ms++;
}

void delay_ms(uint32_t ms) {
    uint32_t start = systick_ms;
    while ((systick_ms - start) < ms);
}

// In main():
SysTick_Config(SystemCoreClock / 1000);

Real-time operating systems for complex embedded applications

What is RTOS?

Intermediate

An RTOS (Real-Time Operating System) provides deterministic, priority-based multitasking for embedded systems. Unlike standard (non-PREEMPT_RT) Linux, an RTOS is designed so that the highest-priority ready task runs within a bounded, predictable time — critical for motor control, medical devices, and industrial automation.

🔨 Bare-Metal

  • Super loop architecture
  • Manual timing via delays
  • Interrupt-driven events
  • Minimal RAM overhead

🔄 RTOS

  • Multi-task architecture
  • Scheduler-managed timing
  • Task synchronization primitives
  • ~2-10 KB RAM overhead

Task Creation

Intermediate

FreeRTOS tasks are infinite loops with vTaskDelay() calls. Each task gets its own stack. The scheduler switches between them based on priority.

freertos_tasks.c 
QueueHandle_t dataQueue;

void TaskBlink(void *params) {
    while (1) {
        GPIOA->ODR ^= (1U << 5);
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

void TaskSensor(void *params) {
    while (1) {
        uint16_t val = adc_read();
        xQueueSend(dataQueue, &val, 0);
        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

int main(void) {
    dataQueue = xQueueCreate(10, sizeof(uint16_t));
    // stack depth is in WORDS (128 words = 512 bytes)
    // higher number = higher priority
    xTaskCreate(TaskBlink,  "Blink",  128, NULL, 1, NULL);
    xTaskCreate(TaskSensor, "Sensor", 256, NULL, 2, NULL);
    vTaskStartScheduler();
    for (;;);  // only reached if the heap ran out
}

Semaphores & Mutexes

Advanced

When multiple tasks share a resource (SPI bus, UART, shared buffer), use a mutex to ensure exclusive access. Only one task can "take" the mutex at a time — others block until it's "given" back.

mutex_example.c 
SemaphoreHandle_t spi_mutex;
// in main(), before the scheduler starts:
// spi_mutex = xSemaphoreCreateMutex();

void TaskA(void *p) {
    while (1) {
        xSemaphoreTake(spi_mutex, portMAX_DELAY);
        spi_transfer(sensor_a_data);
        xSemaphoreGive(spi_mutex);
        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

void TaskB(void *p) {
    while (1) {
        xSemaphoreTake(spi_mutex, portMAX_DELAY);
        spi_transfer(sensor_b_data);
        xSemaphoreGive(spi_mutex);
        vTaskDelay(pdMS_TO_TICKS(200));
    }
}

Priority Inversion

Advanced

Priority inversion occurs when a high-priority task is blocked waiting for a mutex held by a low-priority task, while a medium-priority task runs instead. This was famously responsible for the Mars Pathfinder bug in 1997!

High Priority 🔴 — BLOCKED waiting for mutex
Medium Priority 🟡 — Running (preempts Low!)
Low Priority 🟢 — Holds mutex, can't run

Solution: Priority Inheritance — temporarily boost Low to High's priority so it can finish and release the mutex. FreeRTOS mutexes (xSemaphoreCreateMutex) do this automatically; binary semaphores do not.
